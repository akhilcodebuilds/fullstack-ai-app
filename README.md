# 🤖 AI Smart Analysis Dashboard

A full-stack web application for sentiment analysis, interactive analytics, historical record management, model performance evaluation, and PDF report generation.

**GitHub Repository:** https://github.com/akhilcodebuilds/fullstack-ai-app

---

## 📌 1. Project Overview

The **AI Smart Analysis Dashboard** is a full-stack web application designed to analyze text sentiment and present analytical insights through an interactive dashboard.

The application integrates a React.js frontend, Flask REST API backend, and MongoDB database. It enables users to submit text for sentiment analysis, view prediction results, explore analytical statistics, review historical records, visualize trends, and generate PDF reports.

The application also provides a model performance section for presenting evaluation metrics and confusion matrix information when supported by the backend.

## 🎯 2. Objectives

* Analyze user-provided text and identify its sentiment.
* Display sentiment predictions through an interactive dashboard.
* Store and retrieve analysis records using MongoDB.
* Present analytical summaries and visualizations.
* Provide REST API endpoints for application functionality.
* Evaluate and display model performance using available metrics.
* Generate downloadable PDF reports.
* Demonstrate full-stack development and frontend-backend integration.

## ✨ 3. Key Features

### 3.1 Sentiment Analysis

Accepts text input and displays the sentiment prediction generated by the backend using the configured sentiment analysis method.

### 3.2 Interactive Dashboard

Displays available analysis statistics and summary information through dashboard components.

### 3.3 Analysis History

Retrieves previously stored analysis records so users can review earlier results.

### 3.4 Analytics and Visualizations

Uses interactive charts to present available sentiment statistics and trends.

### 3.5 Model Performance Evaluation

Provides a section for viewing available model evaluation metrics and classification results.

Depending on the backend response, this section can present accuracy, precision, recall, F1-score, class-wise metrics, and a confusion matrix.

### 3.6 PDF Report Generation

Provides a backend endpoint for generating a downloadable PDF report, subject to the implemented report functionality.

### 3.7 MongoDB Integration

Stores and retrieves analysis records through the backend database connection.

### 3.8 REST API Integration

Connects the React frontend to the Flask backend through HTTP requests using Axios.

### 3.9 API Testing

Supports API testing through tools such as Postman.

## 🏗️ 5. System Architecture

The application follows a client-server architecture.

```text
                       User
                         |
                         v
                React Frontend
                     (Vite)
                         |
                         v
                  Axios Requests
                         |
                         v
                   Flask REST API
                         |
             +-----------+-----------+
             |           |           |
             v           v           v
        Sentiment     MongoDB     PDF Report
        Analysis      Database    Generation
             |           |
             +-----------+
                         |
                         v
                   API Responses
                         |
                         v
             Dashboard and Analytics
```

### Architecture Components

* **Frontend:** Collects user input and displays analysis results.
* **Backend:** Processes requests and provides application functionality.
* **Sentiment Analysis:** Calculates sentiment information using the configured analysis method.
* **Database:** Stores and retrieves analysis history.
* **REST API:** Transfers data between the frontend and backend.
* **Reporting:** Generates PDF reports when requested.

---

## 🔄 6. Application Workflow

1. The user opens the dashboard.
2. The user enters text for sentiment analysis.
3. The React frontend sends an HTTP request to the Flask backend.
4. The backend processes the text and generates the sentiment result.
5. The backend stores the analysis record in MongoDB according to its implemented logic.
6. The frontend displays the result.
7. Users can access available statistics, charts, trends, and historical records.
8. Users can view available model evaluation information.
9. Users can request a PDF report through the report API.

## 🔌 8. REST API Endpoints

The following endpoints are used by the application frontend or are part of the documented backend interface.

| HTTP Method | Endpoint                 | Description                                         |
| ----------- | ------------------------ | --------------------------------------------------- |
| GET         | `/`                      | Returns the backend welcome message, if implemented |
| GET         | `/api/health`            | Checks backend availability                         |
| POST        | `/api/sentiment`         | Processes a sentiment analysis request              |
| GET         | `/api/history`           | Retrieves analysis history                          |
| GET         | `/api/stats`             | Retrieves sentiment statistics                      |
| GET         | `/api/trends`            | Retrieves trend information                         |
| GET         | `/api/model-performance` | Retrieves model evaluation information              |
| GET         | `/api/report/pdf`        | Generates or returns a PDF report                   |

The response format, required request fields, and availability of individual endpoints depend on the actual backend implementation.

## ⚙️ 9. Installation and Setup

### 9.1 Prerequisites

Install the following tools:

* Python
* Node.js and npm
* MongoDB
* Git
* Visual Studio Code (recommended)
* Postman (for API testing)

### 9.2 Clone the Repository

Open a terminal and run:

```bash
git clone https://github.com/akhilcodebuilds/fullstack-ai-app.git
cd fullstack-ai-app
```

### 9.3 Set Up the Backend

Navigate to the backend directory:

```powershell
cd backend
```

Create a virtual environment if one does not already exist:

```powershell
python -m venv .venv
```

Activate the virtual environment:

```powershell
.\.venv\Scripts\Activate.ps1
```

Install the backend dependencies.

If `requirements.txt` exists inside the backend directory:

```powershell
pip install -r requirements.txt
```

The backend dependencies used during development included:

* Flask
* Flask-CORS
* PyMongo
* python-dotenv
* vaderSentiment

Use the project's actual dependency file as the authoritative installation list.

### 9.4 Configure MongoDB

Ensure MongoDB is running and configure the backend to connect to the intended database.

The development database used for this project was:

```text
ai_smart_dashboard
```

Set the required MongoDB connection string through the project's environment configuration.

**Security note:** Never commit database passwords, credentials, or secret connection strings to GitHub.

### 9.5 Start the Flask Backend

From the backend directory, run the command appropriate to the application's entry point. For example:

```powershell
python app.py
```

If the application is configured to use Flask on port `5000`, the local backend address may be:

```text
http://127.0.0.1:5000
```

Check the terminal output to confirm that the backend has started successfully.

### 9.6 Set Up the Frontend

Open a second terminal and navigate to the frontend directory from the project root:

```powershell
cd frontend
```

Install the frontend dependencies:

```powershell
npm install
```

Start the development server:

```powershell
npm run dev
```

Open the local URL displayed in the terminal. The default Vite development address is commonly:

```text
http://localhost:5173
```

### 9.7 Verify Frontend-Backend Connectivity

Confirm that:

1. MongoDB is available.
2. The Flask backend starts without errors.
3. The health-check endpoint returns a successful response.
4. The frontend development server starts.
5. The frontend API configuration points to the correct backend address.
6. CORS permits requests from the configured frontend origin.
7. A sample sentiment request returns the expected response.

## 📊 11. Results and Evaluation

The dashboard is designed to present sentiment analysis results, historical records, analytical summaries, and available model evaluation information.

### 11.1 Sentiment Analysis Results

The backend uses VADER Sentiment for text sentiment analysis in the implemented development configuration.

VADER is a rule-based sentiment analysis tool. It calculates sentiment scores and can be used to classify text into positive, negative, and neutral categories according to the application's configured thresholds.

### 11.2 Model Evaluation Metrics

If a separately trained classification model is evaluated, the following metrics can be reported:

* Accuracy
* Precision
* Recall
* F1-score
* Confusion matrix

Include numerical values only when they have been calculated from the actual model and evaluation dataset.

### 11.3 Confusion Matrix

A confusion matrix compares actual class labels with predicted class labels.

For a three-class sentiment classifier, its rows and columns may represent:

* Negative
* Neutral
* Positive

The actual class order must match the labels returned by the backend or the evaluation code.

The confusion matrix can be used to calculate class-wise true positives, true negatives, false positives, and false negatives.

### 11.4 Performance Analysis

Compare evaluation results only when the corresponding models have been tested under consistent conditions using the same evaluation dataset.
